# Модель ветвления

## Выбранная модель

GitHub Flow (упрощённая Flow-модель) с единственной долгосрочной веткой `main`.

## Обоснование

- Команда из 2 человек, один релизный поток, нет параллельной поддержки нескольких версий.
- `main` всегда в рабочем состоянии; релиз = тег на коммите в `main`.
- Gitflow (develop, release, hotfix) избыточен: добавляет ветки и слияния без пользы при такой команде.

## Правила

1. Прямые коммиты в `main` запрещены (Branch Protection).
2. Каждая задача из Jira = отдельная ветка от актуального `main`.
3. Имя ветки: `<тип>/<ключ-задачи>-<краткое-описание>`
   - `feature/TA-7-health-check`
   - `docs/TA-8-readme-run-and-test`
   - `fix/...`, `chore/...`
4. Коммиты по Conventional Commits: `<тип>(<ключ-задачи>): <описание>`
   Типы: feat, fix, docs, chore, refactor.
5. Слияние только через Pull Request с минимум 1 approve и зелёными проверками.
6. Стратегия слияния: squash and merge (одна задача = один коммит в main).
7. После слияния ветка удаляется.
8. Релизы: SemVer, аннотированный тег `vX.Y.Z`, запись в `CHANGELOG.md`.
