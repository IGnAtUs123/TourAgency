# Функциональные требования

Документ составлен на основе диаграммы целевого процесса (`docs/bpmn/to_be.png`) и спецификации требований к системе «Туристическое агентство».

## 1. Требования для роли «Гость» (неавторизованный пользователь)

| ID | Требование |
|---|---|
| FR-01 | Система должна отображать каталог туров без необходимости авторизации. |
| FR-02 | Система должна позволять фильтровать и искать туры по параметрам (направление, даты, цена). |
| FR-03 | Система должна отображать подробную карточку тура (описание, фотографии, цена, доступные места, даты). |
| FR-04 | Система должна предлагать гостю авторизацию/регистрацию при попытке забронировать тур. |

## 2. Требования для роли «Пользователь» (авторизованный клиент)

| ID | Требование |
|---|---|
| FR-05 | Система должна позволять пользователю зарегистрироваться и авторизоваться (email + пароль). |
| FR-06 | Система должна позволять пользователю создать заявку на бронирование выбранного тура. |
| FR-07 | Система должна автоматически проверять доступность мест перед созданием заявки и не допускать бронирование при отсутствии свободных мест. |
| FR-08 | Система должна отображать пользователю список его заявок и их текущий статус (Новая / Одобрена / Отклонена). |
| FR-09 | Система должна уведомлять пользователя об изменении статуса его заявки. |
| FR-10 | Система должна позволять пользователю редактировать свои личные данные (имя, телефон, email). |

## 3. Требования для роли «Администратор»

| ID | Требование |
|---|---|
| FR-11 | Система должна позволять администратору создавать новый тур с указанием описания, цены, дат, количества мест и изображений. |
| FR-12 | Система должна позволять администратору редактировать и удалять существующие туры. |
| FR-13 | Система должна предоставлять администратору список всех заявок на бронирование. |
| FR-14 | Система должна позволять администратору одобрить или отклонить заявку на бронирование. |
| FR-15 | При одобрении заявки система должна автоматически уменьшать количество доступных мест в туре. |
| FR-16 | При отклонении заявки система должна сохранять место доступным для бронирования другими пользователями. |

## 4. Сквозные (кросс-ролевые) требования

| ID | Требование |
|---|---|
| FR-17 | Система должна разграничивать права доступа к функциям в соответствии с ролью пользователя (Гость / Пользователь / Администратор). |
| FR-18 | Система должна хранить историю всех заявок на бронирование для последующей отчётности. |
| FR-19 | Система должна исключать возможность двойного бронирования одного и того же места в туре (конкурентный доступ). |

## Трассировка на точки автоматизации (To-Be)

| Точка автоматизации на диаграмме To-Be | Покрывающие требования |
|---|---|
| Единый каталог туров в БД | FR-01, FR-02, FR-03 |
| Автоматическая проверка доступности мест | FR-07, FR-19 |
| Автоматическое уведомление администратора о заявке | FR-13 |
| Автоматическое обновление статуса и доступности мест | FR-08, FR-15, FR-16 |
| Автоматическое уведомление клиента о решении | FR-09 |
